# 产品规格：Codex 学习制卡插件

> 状态：PROPOSED 设计规格  
> 日期：2026-07-16  
> 本文不表示插件已经实现。

## 1. 产品愿景

让用户不必学习一套制卡软件的内部流水线，只需告诉 Codex：

- 我想学什么；
- 素材在哪里；
- 我期望达到什么行为；
- 我愿意复习多少内容。

系统负责把素材变成可信、可评分、可复习的学习任务，并把最终结果送进 Anki。

产品不是“AI 摘要转闪卡”，而是“有证据的学习目标编译器”：

~~~text
素材 + 学习合同 + 学习者状态
        ↓
证据化语义单元
        ↓
值得复习的学习目标组合
        ↓
可评分卡片计划
        ↓
经过媒体、APKG 和 Anki 验证的结果
~~~

## 2. 首版目标用户

### 2.1 主要用户

- 项目作者本人。
- 熟悉 Codex、Git、模型配置和本地工具的高级用户。
- 愿意授予明确文件/目录权限，并理解本地模型、远程模型和 TTS 的区别。
- 对卡片质量、来源证据、可恢复任务和批量处理有较高要求。

### 2.2 暂不优化的用户

- 完全不使用 Codex 的普通桌面用户。
- 需要组织级多人协作、云同步和权限管理的团队。
- 只想一键生成大量未经审核闪卡的用户。

这不是永久排除，而是首版聚焦。

## 3. 用户要完成的工作

| Job | 用户表达 | 成功结果 |
|---|---|---|
| 从语言素材学习 | “把这个视频里我该学的词块做成卡片” | 候选准确、音视频对齐、可以真实复习 |
| 从文档建立记忆 | “把这份 PDF 中我必须掌握的概念做成卡片” | 目标可作答、证据可定位、概念不被扭曲 |
| 从多个来源建立组合 | “把这个文件夹里的课程资料按考试目标整理” | 去重、冲突可见、覆盖合理 |
| 继续中断任务 | “接着昨天剩下的 26 张做” | 已完成批次不重复收费或重做 |
| 修正 Agent 判断 | “这条太简单，换成应用题” | 用户意图以语义操作保存并影响后续 |
| 导入并证明 | “导入 Anki，确认媒体都能用” | 导入需授权，note/card/media 可核验 |

## 4. 学习合同

每个项目必须有一个轻量 Learning Contract。Agent 可以从对话推断草稿，但在昂贵或不可逆步骤前必须把关键内容展示给用户。

最小字段：

| 字段 | 含义 | 默认策略 |
|---|---|---|
| purpose | 使用目的，如日常表达、考试、工作决策 | 从对话推断；不确定时使用“长期理解” |
| target behavior | 未来希望能做什么 | 优先用行为描述，而非“了解” |
| learner level | 当前水平与已知内容 | 可从历史项目推断，必须允许覆盖 |
| routes | 识别、产出、听辨、应用等 | Agent 推荐一个组合 |
| budget | 新卡数量、每日复习或总时间 | 由保守预算开始 |
| language | 提示、答案和解释语言 | 继承用户偏好 |
| evidence policy | 自动、需审核、只生成草稿 | 按来源质量自动建议 |
| exclusions | 不要学习什么 | 用户锁定后不得覆盖 |

如果缺失信息不会改变安全、成本或学习路线，Agent 应采用可逆默认值继续，不把用户困在问卷里。

## 5. 体验模型

### 5.1 三个角色

- 对话：表达意图、解释决策、处理例外。
- Work Rail：显示权威任务状态、候选、进度、风险和主操作。
- 本地可靠性服务：执行素材、模型、TTS、媒体、导出和 Anki 核验。

对话不能宣称任务成功，除非权威任务快照和产物证据已经确认。

### 5.2 标准主流程

1. 用户添加一个或多个素材。
2. Agent 注册输入并取得稳定快照或明确降级级别。
3. Agent 提议或确认学习合同。
4. 系统解析素材、建立证据定位和语义单元。
5. Agent 生成候选学习目标，通过硬门禁、排序与组合选择。
6. 用户可直接接受，也可筛选、锁定、拆分、合并、改变路线。
7. 系统生成 CardPlan 并验证可作答性、证据和预计复习成本。
8. 本地服务生成卡片正文、TTS、音视频和 APKG。
9. 系统核验包内 note/card/deck/media 和语义清单。
10. 用户点击“导入 Anki 并核验”。
11. 系统先核验真实 Anki 中的 note/card/deck/template/media 数据；只有版本化 runtime verifier 进一步证明正背面渲染、翻面、媒体播放和重启复习，才输出完整 Anki 验证证书。

### 5.3 快速路径

对稳定、低风险、少量输入，用户可说：

> “按我上次的英语学习偏好，从这个视频选 10 个值得主动表达的词块，生成后让我审核。”

若权限、服务和偏好仍有效，Agent 可以直接完成注册、发现、筛选和预览；导入 Anki 仍需明确动作。

## 6. 自治与确认

“最大权限”在产品中解释为“授权范围内最大自治”，而不是任意操作系统权限。

| 动作 | 默认 |
|---|---|
| 读取已明确提供的附件 | 自动 |
| 读取已授予的本地文件/目录 | 自动 |
| 在既有授权域内重新解析或重试 | 自动 |
| 调用已验证、已选择的模型/TTS | 自动；遵守数量与成本上限 |
| 发现、排序、去重候选 | 自动 |
| 排除硬失败卡片 | 自动并解释 |
| 在授权输出目录生成新文件 | 自动 |
| 使用新的目录或扩大目录范围 | 必须确认 |
| 首次向新的远程服务上传内容 | 必须确认 |
| 超出已批准的成本或数量范围 | 必须确认 |
| 安装/更新依赖、插件或 AnkiConnect | V1 不由插件执行；用户在插件外明确操作 |
| 覆盖、删除、迁移用户数据 | 必须确认 |
| 导入或更新 Anki 内容 | 必须明确点击 |
| 执行任意 Shell、SQL、AnkiConnect 透传 | 永不作为公共工具提供 |

确认必须说明：

- 做什么；
- 访问或修改哪些资源；
- 数量和成本上限；
- 是否可以撤销；
- 权限何时过期。

模型/TTS 数据出域、费用和 50+ 批量使用不可变 OperationIntent + 受信本地 UI 批准；Anki 使用不可变 ImportPlan + 独立受信确认。对话中的“我同意”只表达意图，不能写入 approval ledger。

用户可随时从受信本地授权管理器查看并撤销尚未消费的文件/目录/网络/输出授权、模型/TTS OperationApproval 和 Anki ImportApproval。撤销不会伪装成回滚已经完成的远程调用、APKG 或 Anki 写入。

## 7. 功能要求

### 7.1 输入与来源

- PR-001：支持注册 Codex 附件、本地文件、受限目录和 URL。
- PR-002：每个输入必须有稳定引用、修订号或内容哈希。
- PR-003：必须显示是否完整读取，以及未读取的页、文件、媒体段。
- PR-004：同一项目支持多源，并能表达支持、重复和冲突关系。
- PR-005：来源能力按 [素材适配器](SOURCE_ADAPTERS.md) 分级，不以“能打开”冒充“能可靠制卡”。

### 7.2 学习发现

- PR-101：候选必须绑定至少一个 EvidenceAnchor。
- PR-102：候选必须说明未来要回忆或执行的行为。
- PR-103：先通过硬门禁，再进行可解释排序。
- PR-104：选择结果需要覆盖组合，而非只取最高分相似条目。
- PR-105：用户可锁定、排除、拆分、合并和改变学习路线。
- PR-106：用户锁定字段不能被后续 Agent 静默覆盖。

### 7.3 卡片规划与生成

- PR-201：一张卡只有一个核心评分边界。
- PR-202：卡片正面不能泄露核心答案。
- PR-203：答案必须可由来源或明确标注的外部解释支持。
- PR-204：复杂技能可以转为 PracticeTask 或参考笔记，不强制塞入卡片。
- PR-205：批量生成必须可检查点恢复，活动批次可以重试，完成批次不重复调用模型。
- PR-206：模型的 HTML、脚本或任意属性不能直接进入 Anki 模板。
- PR-207：Learning Contract 只能通过 expected revision + 版本化语义操作更新；目的、行为、路线、证据策略、语言、预算或 exclusions 变化按固定矩阵使下游 stale，旧任务不得覆盖新 revision。

### 7.4 交付

- PR-301：严格区分草稿、可导出、APKG 已生成、已导入和已核验。
- PR-302：任何可靠性阻塞存在时，不得输出“已验证”的半成品。
- PR-303：部分失败时自动保留可用项，失败项单独解释，不要求重复确认继续导出。
- PR-304：APKG 必须有哈希、媒体清单和生成审计。
- PR-305：Anki 写入必须由用户明确触发。
- PR-306：VerificationArtifact 以判别状态区分 imported_unverified、data_verified、runtime_failed 与 fully_verified；runtime_failed 只接受 verifier-signed 的可信 failure proof。fully_verified 还必须绑定权威 identity/media、Service-derived 非空 render expectations、root-signed、append-only tombstone 且逐 key-version 永久绑定唯一公钥的 anti-rollback trust set、无环 signed run、launch-attested typed proofs、完整 signed run-owned process lifecycle ledger、add-on focus action attestations、三传感器跨进程零写、对称 typed focus/process/window、真实 isolated-Anki restart，以及可独立重算的 Typed FinalRuntimeEvidenceInputsManifest、barrier-bound final 11-check aggregate 与原子证书提交；撤销快照回滚、外部写后恢复、旧窗口/helper-only 假重启或 post-cutoff TOCTOU 均不能通过。

### 7.5 任务与恢复

- PR-401：超过 500ms 的操作必须有可见反馈。
- PR-402：长任务有权威 StudyTaskSnapshot、取消、超时语义和最后活动时间。
- PR-403：百分比单调；未完成的总体任务不能显示 100%。
- PR-404：任务中断后从最近安全产物恢复。
- PR-405：旧任务结果的输入指纹不匹配时，不得覆盖当前项目。
- PR-406：任务、日志和检查点不得保存密钥、Token 或 Cookie。
- PR-407：Anki 跨会话恢复必须先判定写边界；未写入时新 intent 重新确认，已写入且身份匹配时只核验，无法判定时停止，不得复用已消费批准或盲目重复导入。
### 7.6 能力与本地配置

- PR-501：环境、模型、TTS 和 Anki 使用同一结构化能力快照，历史测试不能覆盖当前失败。
- PR-502：模型/TTS/AnkiConnect 的每个精确 profile 验证绑定配置指纹与 credentialRevision；最新失败覆盖旧成功，配置或凭据变化后自动 stale。
- PR-503：密钥只能在受信本地配置流程写入 OS 凭据存储，不经过对话或 MCP 参数。
- PR-504：插件只查询 secret_exists/profile 状态，不提供秘密回读。
- PR-505：V1 不提供安装、升级或 repair_env 工具；用户只能在插件外明确执行。未来若增加安装能力，必须独立设计、签名验证并由真实用户触发。
- PR-506：启动时必须验证目标宿主能加载插件、启动本地 stdio Service 并注册工具；宿主/插件版本变化使结果 stale。受信本地 UI 不可用时必须降为 APKG-only；runtime verifier 不可用时最多 anki_data_verified，不能伪造完整 Anki 运行时闭环。
- PR-507：插件摄取的所有 raw URL 只在受信本地输入表面录入；公共 MCP 参数不接受 url/origin/query，URL 分类和秘密扫描发生在字符串进入 MCP 之前。

## 8. 状态真相

插件必须分离：

- ProductStep：用户正在看什么。
- ArtifactStage：最远获得了什么可靠产物。
- OperationState：当前任务正在做什么。
- CapabilityState：固定运行时能力与每个精确模型/TTS/AnkiConnect profile 是否可用；聚合状态只展示，不驱动门禁。
- UserNotice：最近一次需要用户理解的结构化结果。

禁止：

- 从自由文本状态猜成功或失败；
- 把“下一动作”显示成“当前页面”；
- 把“APKG 已生成”写成“已在 Anki 验证”；
- 把历史模型测试通过当成当前 OAuth 或代理可用；
- 把没有进度事件误判为成功。

## 9. 范围

### 9.1 0.1 / M3：Language MVP

- Git 仓库/个人 Marketplace 安装。
- Skill + 本地 stdio MCP，核心流程 tools-only 可完成。
- 本地视频/字幕和经过安全获取的公开视频 URL。
- 当前语言 LearningPoint/Card/APKG/Anki 可靠性兼容层。
- 候选选择、卡片计划、生成、APKG、显式 Anki 导入、数据核验与受信 runtime 核验。
- 检查点恢复、内部授权记录和结构化审计。

### 9.2 0.2 / M4–M5：App UI 与稳定文本来源

- App UI 只有在目标 Codex 宿主兼容实验通过后启用；未通过时保持 tools-only。
- TXT/Markdown、文本型 PDF、DOCX/EPUB、HTML 快照、受限文件夹和播客/音频。
- 每种来源独立通过身份、完整性、证据锚和安全适配器门槛。

### 9.3 0.3 / M6：通用 Study IR

- 稳定事实、定义、概念、因果、比较、流程、论点、公式和应用路线。
- 多来源关系、冲突、先修、PracticeTask 和 ReferenceNote。

### 9.4 DEFERRED

- 官方固定右侧栏出现后的宿主适配器。
- 公共目录提交和生产托管 MCP。
- 团队协作、云同步、多租户。
- Codex 关闭后仍持续运行的后台服务。
- 移动端。
- 自动无确认写入 Anki。

## 10. 成功指标

### 产品

- 在通过 M3 兼容矩阵、可启动受信本地选择/确认窗口和版本化 Anki runtime verifier 的宿主上，高级用户不打开完整 Tauri 桌面端即可完成从附件到完整运行时核验的 Anki 卡片；只有 AnkiConnect 时最多承诺数据核验，受信 UI 不可用时只承诺 APKG 导出。
- 正常路径中，用户只在学习选择和高影响动作处被打断。
- 中断恢复不重复已完成的昂贵步骤。
- 对失败给出唯一、可执行的下一动作。

### 可靠性

- 已验证卡片证据锚覆盖率 100%。
- 对声明为 source-supported 的已验证卡，未归因事实 0；现实世界真值另行标示 source_only/externally_corroborated/not_assessed。
- 未解决阻塞冲突进入事实卡 0。
- 静默遗漏来源 0。
- 错误“已核验”状态 0。
- 用户锁定字段被覆盖 0。

### 学习

- 与仅阅读/摘要相比，1、7、30 天提取正确率和单位复习时间收益可测。
- 能区分识别、产出和迁移效果。
- 记录编辑、删除、暂停和遗忘行为，监控复习债务。
- 所有效果声明必须来自预先定义的 benchmark 或实验，不以模型主观评分替代。

## 11. 首版验收

各版本只对已进入范围的闭环负责。0.1 / M3 发布必须通过：

1. 语言视频单卡和至少 20 张批量卡。
2. 本地视频/字幕与公开视频 URL 的语言卡；文本 PDF/网页到 0.2，通用知识到 0.3。
3. M3 输入的完整性、去重和部分失败；多文件目录验收到 0.2。
4. URL、路径、提示注入和秘密泄漏对抗测试。
5. 模型/TTS 断线、取消和进程重启恢复。
6. APKG 导出到不同磁盘并导入 C 盘 Anki 用户目录。
7. 关闭并重启 Anki 后仍可复习，媒体可播放。
8. tools-only 能完成全部核心路径；App UI 仅在 M4 宿主兼容验证后按实际支持形态验收。
9. 所有 PROPOSED 公共接口有契约测试，且不暴露通用内部执行器。
