# 学习设计：如何选出值得制卡的内容

> 状态：PROPOSED 学习设计；部分结论标为 EXPERIMENT  
> 日期：2026-07-16  
> 本文不表示通用知识路线已经实现。

## 1. 第一性原理

一张卡片不是一段被保存的文字，而是一次可以重复、可以评分的记忆提取事件：

~~~text
线索 → 学习者主动作答 → 明确评分边界 → 准确反馈 → 未来间隔提取
~~~

因此卡片最低条件是：

1. 有一个未来值得做出的行为。
2. 正面提供足够但不泄露答案的线索。
3. 学习者能在揭示答案前尝试。
4. 核心答案边界明确，能判断对错或达到程度。
5. 反馈准确，并能追溯到证据或明确标注的解释来源。
6. 复习收益大于未来产生的复习债务。

“一张卡一个目标”指一个可评分的提取目标，不必机械等同于一个词。一个固定语法框架、因果链或决策规则，只要评分边界统一，也可以是一个目标。

## 2. 选择的真正问题

系统不应问：

> 这段材料里最重要的句子是什么？

而应问：

> 对这个学习者、这个目的和未来情境，什么行为值得通过间隔提取练到更可靠？

来源中心性不等于学习价值。文章标题可能很重要，却不适合制卡；一个不显眼的高频词块可能最能改善真实表达。

## 3. 从素材到卡片的学习编译流程

1. 获取授权输入和稳定快照。
2. 解析结构并记录完整性。
3. 建立 EvidenceAnchor。
4. 识别 SemanticUnit：语言形式或知识主张。
5. 将语义单元转成 LearningObjective。
6. 应用硬门禁。
7. 评分、去重、冲突处理和先修关系分析。
8. 做组合选择，覆盖不同路线和难度。
9. 生成 CardPlan。
10. 进行可作答性、证据、泄露和复习成本检查。
11. 生成、导出、Anki 验证。
12. 用真实复习行为更新学习者模型。

格式只决定如何提取；学习目标和知识类型决定做什么卡。

## 4. 硬门禁

任何候选在排序前必须满足：

| 门禁 | 问题 | 失败处理 |
|---|---|---|
| 证据 | 能定位到可靠来源吗？ | 降为草稿或阻塞 |
| 目标相关 | 与 Learning Contract 的未来行为有关吗？ | 排除 |
| 新颖性 | 对该学习者不是已掌握或确定重复吗？ | 合并、降权或排除 |
| 可评分 | 能定义核心正确答案吗？ | 拆分、改路线或转 PracticeTask |
| 适合卡片 | 间隔提取是合适练习吗？ | 转参考笔记或练习任务 |
| 冲突 | 是否存在未解决的来源冲突？ | 事实卡阻塞；可生成“来源分歧”卡 |
| 复习价值 | 预计收益是否超过复习债务？ | 降权或不制卡 |
| 安全 | 是否包含敏感或未经授权内容？ | 阻塞 |

无法通过硬门禁的内容不能靠模型的高置信度绕过。

## 5. 排序维度

通过门禁后计算可解释分数，而不是依赖一个不透明的“推荐度”。

建议维度：

- goalRelevance：与学习合同的相关度。
- futureFrequencyOrStakes：未来出现频率或错误代价。
- bottleneckAndTransfer：是否解除理解/表达瓶颈，能否迁移。
- forgettingOrConfusionRisk：是否容易遗忘或和相近概念混淆。
- evidenceConfidence：证据质量和抽取置信度。
- noveltyAndLearnerFit：对当前学习者是否新且难度适合。
- scoreability：是否能可靠判断回答。
- reviewCost：卡片长度、复杂度和未来复习时间。

排序结果必须能解释，例如：

> 推荐这个词块，因为它在三处素材中出现、符合“主动表达”目标、对 B1 学习者具有高迁移价值；预计复习成本低。来源字幕时间为 00:05:57–00:06:03。

不向用户展示虚假精确的总分小数。内部可保留分项分数，UI 采用理由和相对等级。

## 5.1 候选发现与评审团机制

候选发现和价值判断必须分开，避免一个模型既出题又给自己打分。

建议流水线：

1. 确定性召回：词频、字幕跨度、标题/定义模式、重复、数字/限定、结构关系。
2. 高召回模型：提出可能值得学习的语义单元，允许多报但必须映射证据。
3. 证据验证器：重放定位器，检查 span、限定、归因、时间和极性。
4. 学习设计评审：判断未来行为、路线、评分边界和粒度。
5. 学习者适配评审：根据水平、已知内容、目的和复习预算判断价值。
6. 关系评审：确定重复、覆盖、先修和冲突。
7. 组合器：在预算内形成覆盖良好的 PortfolioSelection。
8. 仲裁器：只处理评审分歧，不重写已验证证据。

评审角色可以由不同模型、同一模型的独立上下文或确定性程序承担。关键不是“模型数量”，而是独立职责、可检查中间产物和失败时不互相背书。

多模型委员会适用于：

- 高价值但证据/路线有分歧的目标。
- 多来源冲突。
- 复杂语用、因果、图表或高风险事实。
- Agent 高置信但验证器给出异常的候选。
- 构建 benchmark 时的独立盲评。

不应对所有普通候选无条件调用委员会，因为它会提高成本、延迟和相关性错误。普通 Tier A 语言 span 可以由确定性验证 + 单模型复核完成。

委员会不得用多数票决定事实。事实门禁仍依赖证据；多数模型同意一个无证据主张，结果仍是 blocked。委员会输出应保留：

- 各角色的结论和 reason code。
- 共同证据和分歧证据。
- 是否需要用户判断。
- 仲裁后保留/降级/拆分/排除的具体理由。

触发用户参与的条件：

- 不同学习路线会导致明显不同的复习行为。
- 用户目标不足以判断重要性。
- 来源冲突不能用范围、时间或归因解决。
- 候选会显著超过复习预算。
- 证据只能达到 Tier B，且内容对用户目的关键。

其余情况 Agent 应自行采用保守、可逆的选择，不把评审团内部讨论原样倾倒给用户。

## 6. 组合选择

简单取 Top-N 会产生十张高度相似的卡。系统需要在预算内做组合优化：

- 覆盖 Learning Contract 中的不同目标。
- 控制同义、同句、同概念簇的数量。
- 平衡识别、产出和迁移。
- 包含适量先修内容。
- 避免大量相同难度或相同线索形式。
- 对高价值主题可生成不同路线，但必须明确它们不是重复卡。

示例：用户要从一次英语访谈选 12 张。

- 5 张高频词块主动产出。
- 2 张听辨。
- 2 张语用/语域。
- 2 张易混表达对比。
- 1 张可迁移语法框架。

实际组合应由素材和学习合同决定，这只是解释模式。

## 7. 语言学习路线

| 路线 | 未来行为 | 正面典型线索 | 核心答案 |
|---|---|---|---|
| reading_recognition | 阅读时识别形式 | 原句或目标表达 | 语义/功能 |
| listening_recognition | 听到时识别 | 原声音频，不显示答案 | 表达或含义 |
| production | 在情境中主动说出 | 中文意图、场景或缺口 | 目标表达 |
| grammar_cloze | 在结构中选出正确形式 | 有控制的挖空句 | 结构片段 |
| pronunciation | 准确发音 | 文字/音位提示 | 学习者口头产出与参考 |
| pragmatics_register | 在合适语境使用 | 情境、关系、正式度 | 表达与使用边界 |
| chunk_collocation | 以词块而非孤词提取 | 语境与搭配槽位 | 固定/半固定词块 |
| contrast | 区分易混表达 | 两个相近选项与语境 | 选择及差异理由 |

语言卡要求：

- 精确目标跨度可验证。
- 原句、字幕时间和媒体片段一致。
- TTS 只读纯文本，不读展示 HTML。
- 无法可靠定位时宁可不高亮。
- 模型生成的标签、脚本和属性必须作为普通文本处理。
- 识别卡与产出卡必须区分，不能用同一题面假装覆盖两种能力。

## 8. 通用知识路线

| 知识类型 | 适合的提取目标 | 不适合的粗糙做法 |
|---|---|---|
| stable_fact | 在限定条件下回忆事实 | 没有时间/范围的孤立数字 |
| definition | 说出区分性定义 | 复制整段百科 |
| concept | 识别概念并区分例/非例 | 只背标签 |
| causal_mechanism | 重建关键因果链 | 把所有细节塞成一个答案 |
| comparison | 按固定维度比较 | “A 和 B 有何不同”但无评分边界 |
| process | 按条件回忆关键步骤 | 机械背所有操作文本 |
| argument | 说出主张、依据和限定 | 把作者意见当事实 |
| formula | 选择/解释/应用公式 | 仅背公式字符 |
| application_transfer | 在新情境使用原则 | 用原文例子原样复述 |
| procedural_decision | 根据条件选择动作 | 没有情境和结果的命令 |
| error_repair | 发现并纠正常见错误 | 只展示正确答案 |

复杂技能如果需要开放式实践、操作环境或多步骤反馈，应该生成 PracticeTask；详细背景可生成 ReferenceNote。卡片不是所有学习内容的唯一容器。

## 9. 粒度判断

粒度过大：

- 答案包含多个独立评分点。
- 一个评分点错误会让整张卡无法判断。
- 学习者通常只记住答案开头。

粒度过小：

- 失去真实语境或意义。
- 产生大量低价值碎片。
- 单卡容易，但不能迁移。

系统应记录 GranularityAssessment：

- atomicity：核心评分边界是否单一。
- contextSufficiency：题面是否提供必要限定。
- answerLength：答案是否可在合理时间提取。
- dependencyLoad：需要同时掌握多少先修。
- splitProposal：若拆分，应如何保持关系。

## 10. 卡片结构

### 正面

- 学习路线标签可选，不显示答案。
- 一个明确任务提示。
- 必要语境、证据片段或媒体。
- 不泄露目标表达。
- 对开放式任务明确评分标准。

### 背面

固定优先级：

1. 核心答案与评分边界。
2. 简短纠错反馈。
3. 来源证据与定位。
4. 解释、中文含义、语用或机制。
5. 音频/视频等媒体。
6. 例句、迁移、反例或相关概念。

背面可以丰富，但核心答案必须在视觉和语义上独立。附加信息不能改变原题的评分边界。

## 11. 证据与解释

每个事实性卡片至少包含：

- 一个 EvidenceAnchor；
- 来源资产和修订；
- 定位器，如页码、段落、字幕时间、DOM 路径；
- 摘录或内容哈希；
- 抽取置信度；
- 是否为来源原意、Agent 解释或外部补充。

Agent 可以补充解释，但必须区分：

- source_direct：来源直接支持。
- source_derived：由来源可重复推导。
- external_corroboration：外部补充且有独立来源。
- pedagogical_example：为教学生成的例子，不得伪装成原文。

## 12. 学习者所有权

原则是：

> Agent-generated, learner-owned。

Agent 负责发现、排序、去重和生成；用户拥有最终学习目标和复习组合。

用户编辑采用语义操作：

- lock：后续不得覆盖。
- exclude：从本项目排除。
- split / merge：改变粒度。
- change_route：从识别改为产出等。
- replace_evidence：更换证据。
- mark_known：加入已知模型。
- suspend：暂不复习。

不使用难以审计的任意 JSON Patch 作为产品级编辑语义。

## 13. 复习债务

每张卡都会产生未来成本。系统在生成前估算：

- 首次理解时间；
- 单次作答时间；
- 预计遗忘/错误频率；
- 媒体加载成本；
- 重复和相似卡干扰；
- 该目标的预期寿命。

用户预算应以“预计每日复习时间”和“新增卡数量”双重表达。高数量不是成功指标。

## 14. 从真实复习更新选择

DEFERRED/EXPERIMENT：

- 用 Anki 作答结果、响应时间、编辑、删除和暂停更新学习者模型。
- 识别“高置信错误”：Agent 很确定但用户反复答错或认为错误。
- 降低长期零收益卡片的优先级。
- 对频繁混淆内容建议对比卡，而不是继续生成孤立定义。
- 保留可解释原因，允许用户关闭个性化。

## 15. 科学依据与边界

检索练习和间隔提取有较强研究基础，但研究结果不能自动证明某种 AI 选卡策略有效。迁移、卡片自生成效应和具体材料类型受任务、反馈与学习者差异影响。因此本项目把学习效果作为需要验证的产品假设。
