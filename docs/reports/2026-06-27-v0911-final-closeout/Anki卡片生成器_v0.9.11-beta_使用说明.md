# Anki 卡片生成器 v0.9.11-beta 使用说明

## 1. 这是什么

Anki 卡片生成器是一个 Windows 桌面端视频制卡工具。它把本地视频 + 字幕，或公开视频链接，转换成可审核、可导出、可导入 Anki 的 `.apkg` 学习卡包。

v0.9.11-beta 的产品原则已经收口：用户侧只有一种卡，叫“学习卡”。系统内部仍会识别词伙、单词用法、语法、听辨、语气等学习点类型，但这些只是筛选和解释维度，不再让用户面对听力卡、表达卡、语法卡等多套相似卡型。

一张学习卡的核心结构：

- 正面：英文原句、视频片段、原声、整句 TTS、目标表达 TTS。
- 反面：目标单词 / 词伙 / 表达、中文解释、语境义、用法提醒，以及必要的听辨或语气提醒。

## 2. 安装和启动

1. 打开本文件夹里的“安装包”目录。
2. 普通用户优先运行 `Anki卡片生成器_v0.9.11-beta_安装程序.exe`。
3. 如果公司环境不允许 exe 安装，可尝试 MSI 包；如果只想临时体验，可解压便携版 zip。
4. 安装后从开始菜单或安装目录启动 Anki Card Generator。
5. 正常启动只应该出现桌面 UI，不应该额外弹出黑色终端窗口。

如果仍看到黑色终端窗口，请先确认是否启动了旧版本、开发调试入口，或从源码目录运行了开发命令。正式安装包的普通启动路径已经隐藏 console。

## 3. 第一次使用前必须检查的环境

进入 `设置 -> 本地环境`，点击“检查环境”。应用会检测：

- Python：运行本地 worker、生成 APKG。
- FFmpeg：切视频、切原声、生成封面和媒体文件。
- yt-dlp：下载公开视频链接和字幕。
- Anki：用于导入和预览卡包。
- AnkiConnect：用于导入后核验 note、card、media。

如果检测失败，请优先使用“一键修复全部可修复项”。AnkiConnect 需要在 Anki 内安装插件，插件代码是 `2055492159`。

## 4. 模型 API 配置

进入 `设置 -> 模型 API`。

### Vertex / Gemini

Vertex 模式使用本机 `gcloud` OAuth，一般不需要在应用里填写 API Key。使用前请确保：

1. 已安装 Google Cloud CLI。
2. 已运行 `gcloud auth login`。
3. 已运行 `gcloud config set project <你的项目 ID>`。
4. 项目中已开启 Vertex AI 相关权限。

当前可用的 Vertex 模型包括 `gemini-3.5-flash`、`gemini-3.1-pro-preview` 等。`gemini-3.5-flash` 速度快、适合批量初筛，但卡片解释质量可能不如更强模型稳定；如果你追求最终卡片质量，可以选择更强的 Pro 类模型。

### OpenAI-compatible / DeepSeek / Qwen / MIMO

这类服务通常需要填写 Base URL、Model 和 API Key。请注意：

- API Key 只保存在本机凭据或本机加密配置中，不应该出现在截图、日志、issue、README 或 GitHub 仓库里。
- 每个模型方案单独保存，避免把文本模型 Key 和 TTS Key 混用。
- 保存后必须点击“测试连接”，测试通过后再正式抽取学习点。

## 5. TTS 配置

进入 `设置 -> 语音 TTS`。

视频学习卡依赖两类声音：

- 原视频音频：来自视频切片。
- AI TTS：用于整句慢读和目标表达朗读。

v0.9.11-beta 仍把 TTS 作为视频学习卡的重要质量闸。TTS 失败时，应用不会静默导出残缺 APKG，而是会显示失败条目、失败原因和重试入口。

Vertex TTS 同样使用本机 `gcloud` OAuth；其它 OpenAI-compatible Speech 服务需要单独配置 Key、Base URL、模型和 voice。

## 6. 从本地视频 + SRT 制卡

1. 在主界面选择“本地视频”。
2. 选择视频文件。
3. 选择 SRT/VTT 字幕；如果留空，应用会尝试同目录自动匹配字幕。
4. 填写学习包标题。
5. 进入学习设置，选择语言、水平、完整复读或快速复读。
6. 点击顶部“抽取学习点”。
7. 等待 AI 扫描字幕并给出推荐、候选和需复查学习点。
8. 使用默认推荐，或点击“全选可制卡项”。
9. 点击“生成 APKG · N 个学习点”。
10. 在审核页点击“全选可导出”，确认数量后导出 APKG。

## 7. 从视频链接制卡

1. 选择“视频链接”。
2. 粘贴 YouTube 或公开视频 URL。
3. 应用会通过 yt-dlp 下载视频和字幕。
4. 如果下载失败，常见原因包括网络、区域限制、字幕不可用、YouTube 429、yt-dlp 版本过旧。
5. 下载和字幕解析通过后，后续流程与本地视频相同。

## 8. 学习点筛选逻辑

应用不是把字幕逐句硬切成卡，而是先筛“值得学习的点”。推荐优先级大致遵循：

- 能迁移到新句子的词伙、搭配、短语动词、句型框架优先。
- 能帮助听懂真实口语的弱读、连读、缩读、语气风险会被保留。
- 目标表达必须能在原句中清楚定位。
- 纯主题名、专有名词堆、弱名词块、疑似坏字幕或 ASR 拼接错误不会默认推荐。
- “需复查但合法”的学习点可以被用户全选进入生成队列，但重复折叠和不可制卡项不会进入。

按钮含义：

- `只选推荐`：只选择系统认为最稳的学习点。
- `全选可制卡项`：选择推荐、候选、需复查但合法的学习点。
- `清空选择`：取消全部选择。
- `显示需复查`：查看需要用户判断的合法学习点。

## 9. 生成和导出时怎么看数量

请区分三个数量：

- 学习点数量：你准备让系统制卡的学习点个数。
- 生成卡片数量：模型和 fallback 生成出的学习卡数量。
- 可导出卡片数量：通过媒体、TTS、字段和质量闸后，真正能写入 APKG 的卡片数量。

如果你选了 N 个学习点，但最后只有 K 张可导出，审核页会显示差异和原因，并提供：

- 继续导出 K 张。
- 重试失败项。
- 返回学习点调整。

## 10. Anki 导入和核验

导出 APKG 后，建议使用“导入并核验”。应用会尽量检查：

- note/card 数量。
- 视频、音频、TTS、封面媒体是否存在。
- 卡片字段是否完整。
- 媒体引用是否丢失。
- AnkiConnect 是否能读取导入后的内容。

如果 Anki 或 AnkiConnect 不可用，APKG 仍可手动导入 Anki，但自动核验会显示环境缺失。

## 11. 常见问题

### 为什么有些学习点显示不可制卡？

通常是目标表达无法在原句中定位、字幕明显异常、重复项被折叠、字段缺失或媒体/TTS 阶段存在硬失败。不可制卡项不会进入“全选可制卡项”。

### 为什么我全选后不是所有东西都生成？

v0.9.11-beta 的全选是“全选可制卡项”，不是强行生成所有扫描到的文本。重复折叠和硬阻断项会被排除。合法但模型漏返的学习点会自动重试一次，并尽量补成基础学习卡。

### 为什么 TTS 失败就不导出？

视频学习卡的正面需要 TTS 支撑复读。如果静默导出缺 TTS 的卡，用户复习体验会很差，所以应用会阻止残缺 APKG，并显示失败原因和重试入口。

### 为什么 Vertex 3.5 Flash 质量有时不稳定？

Flash 模型速度快、成本低，但复杂语境解释和严格 JSON 输出可能不如更强模型稳定。建议用它做批量初筛；重要素材或长视频可以切换到更强模型重新生成。

### 公开分享卡包需要注意什么？

第三方视频、字幕、原声和合成音频可能涉及版权。默认建议仅个人学习使用。公开分享前请确认你拥有分发素材和字幕的权利。

## 12. 隐私和安全

- 不要把 API Key 上传到 GitHub、issue、截图或日志。
- 模型 API 和 TTS 会把字幕、学习点、卡片字段或 TTS 文本发送给你配置的服务商。
- 本地生成的视频片段、音频、APKG、缓存和项目数据默认只在本机。
- 卸载程序本体不会自动删除 AppData、API Key、历史项目或 Anki 数据。
